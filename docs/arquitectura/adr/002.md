# [ADR-002] Utilizacion de Kong API Gateway

* **Estado:** Propuesto
* **Decisores:** Hector de Jesus Camargo Villafan
* **Stakeholders:** IT
* **Fecha:** 2026-11-11

---

## 1. Contexto y Declaración del Problema

La organización cuenta con un ecosistema tecnológico compuesto por aplicaciones web, móviles y servicios de terceros que consumen múltiples APIs. A medida que la arquitectura ha evolucionado hacia microservicios, aumentó considerablemente la cantidad de endpoints y las integraciones entre sistemas internos y externos.

---

## 2. Opciones Consideradas

Enumere las alternativas técnicas o de arquitectura evaluadas para resolver el problema:

* **Opción 1:** Mantener la gestión distribuida en cada microservicio
* **Opción 2:** Desarrollar un API Gateway propio
* **Opción 3:** Utilizar servicios administrados de API Gateway en la nube

---

## 3. Decisión Tomada

Decidimos seleccionar la **[Opción 1]** porque se gestionara la distribuicion de peticiones.

### Razones Principales de la Elección
* Razón 1: Resuelve el cuello de botella entre los microservicio y el monolito.

---

## 4. Análisis Comparativo de Opciones (Pros y Contras)

### Opción 1: distribuicion de cargas

* **Ventajas:**
  * mejor distribuicion de carga de peticiones
  * mantener la conexion entres los microservivios
* **Desventajas:**
  * redistribuicion a un solo componente
